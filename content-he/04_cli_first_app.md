# פרק 4. ה-CLI, האפליקציה הראשונה שלך, והאנטומיה של פרויקט Angular

הפרק הזה שונה משלושת הקודמים. הוא הפרק הראשון שכדאי לך לקרוא *עם המחשב הנייד שלך פתוח*. עד סוף הפרק, Compass יתקיים כפרויקט בדיסק שלך, שרת הפיתוח שלו ירוץ, ועמוד ההתחלה שלו יהיה פתוח בדפדפן שלך. ואז נעבור על כל קובץ שה-CLI של Angular ייצר, כך ששום דבר בפרויקט החדש שלך לא ייראה מסתורי בפעם הראשונה שתפתח אותו בעורך.

אם נתקעת בהתקנת Node.js, קפוץ לנספח א' להערות ספציפיות לפלטפורמה. חזור כשיהיה לך `node --version` ו-`npm --version` עובדים במסוף שלך.

## מה אנחנו מתקינים, ולמה

אתה צריך שלושה דברים כדי לעבוד על Angular:

1. **Node.js** — סביבת ריצה שמאפשרת ל-JavaScript לרוץ מחוץ לדפדפן. כלי הפיתוח של Angular (הקומפיילר, שרת הפיתוח, מריץ הבדיקות) הם תוכניות JavaScript; הן רצות על Node.js. תתקשר עם Node.js ישירות מעט מאוד, אבל הכל תלוי בו.

2. **npm** — מנהל החבילות של Node.js. הוא מגיע יחד עם Node.js. הוא מוריד ספריות — כולל את Angular עצמה — לתוך תיקייה שנקראת `node_modules` בתוך הפרויקט שלך.

3. **ה-CLI של Angular** — הפקודה `ng`. זה כלי שמייצר תבניות של פרויקטים חדשים, יוצר קבצים חדשים, מריץ את האפליקציה שלך, מריץ את הבדיקות שלך, ובונה להפקה. כל מה שתעשה עם Angular לשארית הספר עובר דרך `ng`.

## התקנת Node.js

לך ל-`nodejs.org` והורד את גרסת ה-**LTS** (long-term support). בזמן כתיבת הספר זו Node.js 20; כשתקרא את זה זה כנראה יהיה Node.js 22 או מאוחר יותר. כל אחת מהן בסדר כל עוד היא 20 ומעלה; Angular מסרבת להתקין על גרסאות ישנות יותר.

עקוב אחרי המתקין לפלטפורמה שלך. ב-macOS וב-Windows, המתקין ממקם את `node` ו-`npm` ב-`PATH` שלך אוטומטית; ב-Linux, השתמש במנהל החבילות של ההפצה שלך או ב-tarball באתר Node.js (ראה נספח א').

פתח מסוף — אפליקציית *Terminal* ב-macOS, *Windows Terminal* או *PowerShell* ב-Windows, אמולטור המסוף האהוב עליך ב-Linux — ואמת:

```bash
node --version    # v20.x.x או גבוה יותר
npm --version     # 10.x.x או גבוה יותר
```

שניהם צריכים להדפיס מספר גרסה. אם אחד מהם אומר "command not found", ראה נספח א'.

## התקנת ה-CLI של Angular

עם Node.js במקומו, התקן את ה-CLI גלובלית עם npm:

```bash
npm install --global @angular/cli
```

הדגל `--global` הופך את `ng` לזמין בכל מקום במחשב שלך, במקום רק בתיקייה של פרויקט אחד. אמת:

```bash
ng version
```

אתה אמור לראות את גרסת ה-CLI של Angular, בתוספת כותרת שמפרטת את החבילות שיותקנו. אם אתה מקבל "command not found", פתח חלון מסוף חדש — ה-shell צריך להבחין בבינארי המותקן החדש.

> **הערה.** יש אנשים שמעדיפים אף פעם לא להתקין שום דבר גלובלית. אם זה אתה, אתה יכול להשתמש ב-`npx @angular/cli` במקום `ng` בכל מקום בספר הזה. זה מוריד עותק זמני בכל פעם. זה איטי יותר אבל שומר על הסביבה הגלובלית שלך נקייה.

## יצירת Compass

בחר תיקייה לשמור בה את הפרויקטים שלך. בספר הזה אשתמש ב-`~/dev`. תחליף בשלך אם אתה מעדיף.

```bash
cd ~/dev
ng new compass
```

ה-CLI שואל אותך כמה שאלות. תענה עליהן כך:

- **Which stylesheet format would you like to use?** → `CSS`. לא נשתמש ב-Sass בספר הזה. אם אתה כבר יודע Sass, אתה יכול לבחור בזה; הקוד עדיין יעבוד.
- **Do you want to enable Server-Side Rendering (SSR)...?** → `No`. נוסיף SSR בפרק 18, ברגע שהאפליקציה תהיה שווה prerender.
- **Which type of routes would you like to configure?** — אם זה מופיע, בחר בברירת המחדל (server routes with data prefetching אם מוצע; אחרת השאר ניתוב מופעל). CLIs חדשים יותר עושים את זה אוטומטית בלי לשאול.

ה-CLI יוצר תיקיית `compass` לצד המקום שבו הרצת את הפקודה, מוריד כמאתיים חבילות ל-`node_modules` (זה ייקח דקה או שתיים בפעם הראשונה), ועוצר. אז הוא משאיר אותך בפרומפט עם רמז קטן על `ng serve`.

קח את הרמז הזה:

```bash
cd compass
ng serve --open
```

כמה שניות אחר כך, הדפדפן שלך ייפתח ב-`http://localhost:4200` ותראה את עמוד ההתחלה של Angular ברירת המחדל. ברכות — אתה מריץ אפליקציית Angular.

`ng serve` גם נשאר פתוח במסוף שלך, ומסתכל על קבצי המקור שלך. שמור שינוי, והדפדפן יטען מחדש אוטומטית. השאר את `ng serve` רץ בחלון מסוף אחד; פתח חלון מסוף שני לשארית הפרק.

## סיור על כל קובץ שה-CLI ייצר

פתח את `~/dev/compass` בעורך שבחרת. אם אין לך עורך מועדף, התקן את **Visual Studio Code** מ-`code.visualstudio.com` ופתח את התיקייה עם `File → Open Folder`. ל-VS Code יש את התמיכה הכי טובה מקופסה ב-Angular מכל עורך חינמי; כשנתחיל לכתוב קומפוננטות בפרק 5, הודעות השגיאה שלו inline יחסכו לך הרבה זמן.

אנחנו הולכים לצעוד עכשיו דרך כל קובץ וכל תיקייה ברמה העליונה. זה הליכה ארוכה. אל תנסה לשנן; רק תיצור מפה מנטלית של מה כל דבר עושה. תפגוש כל אחד מהקבצים האלה שוב, בהקשר, בהמשך הספר.

### `package.json`

זה התיאור של הפרויקט שלך מבחינת npm. שני חלקים שווים בדיקה.

`scripts` מפרט את הפקודות שאתה יכול להריץ דרך `npm run <name>`:

```json
"scripts": {
  "ng": "ng",
  "start": "ng serve",
  "build": "ng build",
  "watch": "ng build --watch --configuration development",
  "test": "ng test"
}
```

`npm run start` ו-`ng serve` שווי ערך. יש קונבנציות שמעדיפות `npm run` כי הוא שומר על אותן פקודות עובדות בפרויקטים שמשתמשים בכלים בסיסיים שונים; בפרויקט Angular אתה יכול להשתמש בכל אחד.

`dependencies` מפרט את הספריות שהאפליקציה שלך צריכה בזמן ריצה; `devDependencies` מפרט את הכלים שהיא צריכה במהלך פיתוח. כשגרסה חדשה של Angular יוצאת ואתה רוצה לעדכן, אתה עורך את מספרי הגרסה האלה או מריץ `ng update` — נושא ליום אחר.

### `angular.json`

קובץ התצורה של ה-CLI. הוא אומר ל-Angular איך לבנות, להגיש, ולבדוק את הפרויקט. תערוך אותו ידנית לעתים רחוקות בפרקים הראשונים; נבקר בו בפרק 16 (ביצועים) ובפרק 19 (פריסה). לעת עתה, דע שהוא קיים.

### `tsconfig.json` וחבריו

שלושה קבצי תצורת TypeScript:

- `tsconfig.json` — התצורה הבסיסית.
- `tsconfig.app.json` — התצורה שנמצאת בשימוש כשבונים את האפליקציה עצמה.
- `tsconfig.spec.json` — התצורה שנמצאת בשימוש כשמריצים בדיקות.

לא תיגע בהם עד שתתחיל לכתוב בדיקות בפרק 17. הקובץ הראשי מפעיל *מצב strict* כברירת מחדל בפרויקטי Angular מודרניים, שפירושו ש-TypeScript תהיה קפדנית לגבי בדיקות `null`, `any` implicit, ורגלי-פיתיון אחרות. אל תכבה מצב strict. זו הסיבה שהאפליקציה שלך תישאר ניתנת ל-refactor שנה מהיום.

### `.editorconfig`

קובץ זעיר שמספר לעורך שלך על הזחה, סופי שורה, ובסיסים אחרים. אם העורך שלך מבין אותו (רובם המודרניים מבינים, לפעמים עם תוסף), הפורמט שלך יתאים אוטומטית לברירות המחדל של ה-CLI.

### `.gitignore`

קובץ שמפרט מה git לא צריך לעקוב אחריו. במיוחד הוא לא כולל את `node_modules/` (שהיא ענקית וניתן לשחזר אותה מ-`package.json`) ואת `dist/` (פלט הבנייה). ניצור מאגר git בעוד רגע.

### `node_modules/`

החבילות המותקנות. Angular עצמה חיה כאן, יחד עם כל מה ש-Angular תלויה בו ובכל מה שתתקין מאוחר יותר. אל תבדוק את התיקייה הזאת לתוך git; היא לעתים קרובות גיגה-בייטים בגודל וניתן לשחזר אותה במלואה עם `npm install`. אם תמחק אותה, תוכל ליצור אותה מחדש עם `npm install`.

### `public/`

קבצים סטטיים שמוגשים כמו שהם בשורש האפליקציה שלך. אם תפיל `robots.txt` או `favicon.ico` כאן, הם יופיעו ב-`/robots.txt` וב-`/favicon.ico` באפליקציה הרצה. ה-CLI מפיל `favicon.ico` ברירת מחדל כאן.

### `src/index.html`

פתח אותו. הוא מאוד קצר:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Compass</title>
  <base href="/">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="icon" type="image/x-icon" href="favicon.ico">
</head>
<body>
  <app-root></app-root>
</body>
</html>
```

האלמנט `<app-root>` הזה הוא נקודת עגון יחידה לכל האפליקציה. כשהדפדפן טוען את הדף, Angular מתאתחלת, מוצאת את האלמנט הזה, ומשתלטת עליו. כל מה שאתה רואה ב-`http://localhost:4200` מרונדר בתוך `<app-root>`.

תערוך את `index.html` לעתים רחוקות. תערוך את הכותרת שלו, מדי פעם תוסיף `<link>` לפונט, ותשאיר אותו לבד.

### `src/styles.css`

CSS גלובלי. כל מה שיש כאן חל על כל האפליקציה. ייבואי פונטים, reset של CSS, ומאפיינים מותאמים אישית ברמת השורש (משתני CSS) חיים כאן. סגנונות ספציפיים לקומפוננטה — הסגנונות של שורת משימה, נניח — חיים בקובץ הקומפוננטה, שנפגוש בפרק 5.

### `src/main.ts`

קובץ ה-bootstrap. מאוד קצר:

```ts
import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { App } from './app/app';

bootstrapApplication(App, appConfig)
  .catch(err => console.error(err));
```

`bootstrapApplication` אומר: "התחל את אפליקציית Angular, שהקומפוננטה השורשית שלה היא `App` והתצורה שלה היא `appConfig`, באיזה אלמנט ב-HTML שיש לו את התג המוגדר על ידי הסלקטור של `App`". התוצאה היא ש-`<app-root>` ב-`index.html` מתמלא בקומפוננטה השורשית המרונדרת.

תערוך את `main.ts` כמעט אף פעם — אולי פעם אחת בפרק 18 כדי לאפשר רינדור בצד השרת.

### `src/app/`

זה איפה שהאפליקציה שלך חיה. כל מה שתכתוב מפרק 5 והלאה נכנס ל-`src/app/` או לתת-התיקיות שלו. ה-CLI כבר שם כאן שלושה קבצים:

**`app.ts`** (או `app.component.ts` בכמה גרסאות CLI) — הקומפוננטה השורשית. בערך:

```ts
import { Component, signal } from '@angular/core';
import { RouterOutlet } from '@angular/router';

@Component({
  selector: 'app-root',
  imports: [RouterOutlet],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {
  protected readonly title = signal('compass');
}
```

ארבעה דברים שכדאי לשים לב אליהם, שאף אחד מהם אתה לא צריך *להבין* עדיין:

- הדקורטור `@Component`. הוא אומר ל-Angular שהמחלקה הזאת היא קומפוננטה, ומגדיר את הקומפוננטה עם סלקטור (`<app-root>`), קובץ תבנית, קובץ סגנון, וכל קומפוננטות או דירקטיבות אחרות שהקומפוננטה הזאת משתמשת בתבנית שלה.
- גוף המחלקה. כל דבר שהקומפוננטה רוצה לחשוף לתבנית שלה נכנס כאן — שדות, מתודות, סיגנלים.
- הקריאה `signal(...)`. זה הפרימיטיב של מצב ריאקטיבי מודרני של Angular. התבנית יכולה לקרוא `title()` והיא תרונדר מחדש אם הסיגנל אי פעם ישתנה.
- `imports: [RouterOutlet]`. קומפוננטות עצמאיות מכריזות אילו קומפוננטות ודירקטיבות אחרות הן משתמשות. `RouterOutlet` הוא ה-placeholder שבו ה-router ירנדר עמודים.

כל פרק מפרק 5 והלאה מבלה זמן בתוך קומפוננטות כמו זו. אל תדאג לפרש אותה עכשיו.

**`app.html`** — התבנית של הקומפוננטה השורשית. ה-CLI ממלא את זה עם עמוד התחלה ממותג של Angular. תמחק את רובו בפרק 5.

**`app.css`** — סגנונות scoped ל-cקומפוננטה השורשית. כל מה שתכתוב כאן חל על `<app-root>` ולא על שום דבר אחר — גם אם יש לך class בשם `.container` בקובץ הזה ועוד class בשם `.container` במקום אחר, הם לא יתנגשו. זה נקרא *view encapsulation*, וזה אחד הדברים הטובים בשקט לגבי כתיבת Angular.

**`app.config.ts`** — תצורה ברמת האפליקציה.

```ts
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideRouter(routes),
  ],
};
```

`providers` היא הרשימה של שירותים ותצורה שהאפליקציה שלך הופכת לזמינים בכל מקום. ב-Angular מודרנית, רוב הדאגות החוצות-רוחביות מוקמות על ידי קריאה לפונקציות `provideX()` כאן — ניתוב, HTTP, אנימציות, וכן הלאה. נוסיף כמה מהן בפרקים מאוחרים יותר.

**`app.routes.ts`** — רשימה ריקה בהתחלה של הגדרות ניתוב:

```ts
import { Routes } from '@angular/router';

export const routes: Routes = [];
```

## מה ה-CLI יכול לעשות מלבד `new` ו-`serve`

תרגל את ההרגל של שימוש ב-`ng generate` לבניית תבניות. זה חוסך הקלדה, ויותר חשוב, זה מציב קבצים חדשים במקום הנכון עם הייבואים הנכונים.

```bash
ng generate component task-row      # יוצר src/app/task-row/*
ng generate service tasks           # יוצר src/app/tasks.service.ts
ng generate pipe date-friendly      # יוצר src/app/date-friendly.pipe.ts
```

אתה יכול לקצר ל-`ng g c task-row`. בספר הזה תמיד נקליד את הצורה הארוכה כדי שתדע מה אתה עושה; בפרקטיקה יומית תקצר.

פקודות אחרות ששוות לדעת:

```bash
ng serve          # שרת פיתוח; מסתכל על קבצים, טוען מחדש בשמירה
ng build          # בנייה להפקה לתוך dist/
ng test           # מריץ את בדיקות היחידה
ng lint           # מריץ את ה-linter, אם מוגדר
ng update         # מעדכן את Angular וחבילות קשורות
```

## לוודא שהכל עובד

עם `ng serve` עדיין רץ מקודם, פתח את `src/app/app.html` בעורך שלך. מצא את ה-`<h1>` הראשון (או מקום עם טקסט גלוי) ושנה טקסט כלשהו ל-`Hello, Compass.`. שמור את הקובץ.

טאב הדפדפן שלך אמור להתרענן תוך שנייה, והטקסט החדש אמור להופיע. אם כן, יש לך סביבת פיתוח Angular עובדת.

אם לא — העמוד לא מתעדכן, או שהמסוף מדפיס שגיאה — ראה את סעיף פתרון הבעיות בנספח א', או את נספח ב', שהוא מדריך לקריאת הודעות שגיאה של Angular.

## מה בא הלאה

חלק שני. בפרק 5 נמחק את רוב תוכן ההתחלה של ה-CLI ונבנה את הקומפוננטה האמיתית הראשונה של Compass: רשימה של משימות. תפגוש תבניות, קישורי נתונים, ואת תחביר בקרת הזרימה החדש. עד סוף פרק 5, Compass תהיה רשימת מטלות — פשוטה מאוד, רצה כולה בדפדפן, בלי כל השמירה, הניתוב או האימות של המוצר המוגמר. כל פרק עוקב מוסיף עוד יכולת אמיתית אחת.

### תרגילים

1. הרץ `ng generate component about --skip-tests --dry-run` וקרא את הפלט. הדגל `--dry-run` אומר ל-CLI להדפיס מה הוא היה עושה בלי לעשות זאת בפועל. אילו קבצים היו נוצרים? עשה את אותו הדבר עבור `ng generate service auth --dry-run`. זה הרגל שימושי לתצוגה מקדימה של מה ה-CLI רוצה לעשות לפני שהוא עושה זאת.

2. פתח את כלי הפיתוח של הדפדפן (F12 ברוב הדפדפנים) ולחץ על טאב "Elements" או "Inspector". מצא את האלמנט `<app-root>` ב-DOM. שים לב שהוא אלמנט אמיתי בעמוד, והתוכן של האפליקציה מרונדר בתוכו. זה שווה לראות פעם אחת כדי שתדע ש-Angular לא עושה שום דבר קסום ל-HTML.

3. ב-`src/app/app.html`, שים `{{ title() }}` איפשהו שהטקסט יהיה גלוי, ושמור. שים לב לסוגריים אחרי `title` — זה לא טעות הקלדה. סיגנלים הם פונקציות שאתה קורא להן כדי לקבל את הערך הנוכחי שלהן. בפרק 7 נבחן למה. לעת עתה, פשוט תבחין שזה עובד.
